# 蒸馏数据集生成套件 · 02-数据规范与示例

> 配套脚本：`scripts/蒸馏数据批量生成.py`
> 任务分类定义见：`01-写作任务分类标准_v1.0.md`
> 目标：用老师模型（本地 LM Studio / Ollama）在台式机上批量生成 **2000–5000 条**高质量中文写作样本，供后续 LoRA 微调使用。

---

## 1. JSONL 数据格式规范

每行一个独立 JSON 对象，UTF-8 编码，字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `task` | string | 任务代号，八类之一：`xuxie` 续写 / `gai_xie` 改写润色 / `fengge` 风格仿写 / `piping` 批评修改 / `kuoxie` 扩写 / `suoxie` 缩写 / `dagang` 提纲大纲 / `biaoti` 标题 |
| `instruction` | string | 给学生模型的指令（微调时的 instruction），描述任务要求 |
| `input` | string | 输入文本 |
| `output` | string | 高质量标准答案，学生模型要学到这个水平 |
| `metadata` | object | `teacher_model`（老师模型名）、`created_at`（日期）、`lang`（固定 `zh`）、`license_note`（固定 `"Qwen系列允许输出用于训练"`） |

**两种样本模式**（由任务性质决定，见第 3 节模板）：

- **A. 改写对模式（平庸版→大师版）**：`input` = 平庸版/原文，`output` = 大师改写版。适用：`gai_xie`、`suoxie`、`fengge`、`piping`。
- **B. 生成模式**：`input` = 种子（开头/梗概/创意），`output` = 高质量生成。适用：`xuxie`、`kuoxie`、`dagang`、`biaoti`。老师在生成时须先在心里避开"平庸版"的常见毛病（情节原地踏步、人物只说不做、没有感官细节、形容词堆砌）。

## 2. Teacher Prompt 模板（喂给老师模型用的提示词）

### 通用要求（拼在每条模板最前面）

```
你是一位中文写作大师，正在为"纯写作专用"小模型生成训练样本。
硬性要求：
1. 只输出一个纯 JSON 对象，不要 markdown 代码围栏、不要解释、不要多余文字。
2. JSON 只有两个键："input"（给学生的输入）和 "output"（高质量标准答案）。
3. 全中文，标点规范，不夹杂英文解释。
4. 严禁出现"作为AI""我是一个语言模型""抱歉"等话术。
```

### 模板 1 · 续写 `xuxie`（B 模式）

```
续写。先在心里写出"平庸续写"并避开它的全部毛病（情节原地踏步、人物只说不做、没有感官细节），
直接输出大师级续写作为 output：情节向前推进、人物有具体行动、有感官细节、结尾留一个钩子。
input 为下面的（原样使用，一个字不改）。
{seed}
只输出 JSON。
```

### 模板 2 · 改写润色 `gai_xie`（A 模式）

```
改写润色。input 字段请原样使用下面的（一个字都不要改动）；
output 为大师改写版：保留原意与关键信息，修正病句，升级意象、节奏与文字质感。
{seed}
只输出 JSON。
```

### 模板 3 · 风格仿写 `fengge`（A 模式）

```
风格仿写。种子格式为"范文：……\n待改写：……"。
先分析的风格特征（句式、节奏、意象、用词），input 为原文（原样使用，不要改动），
output 为按范文风格改写后的版本：只学风格不抄范文内容，意思与待改写一致。
{seed}
只输出 JSON。
```

### 模板 4 · 批评修改 `piping`（A 模式）

```
批评并修改。input 为下面的（原样使用，一个字不改）；
output 分两部分：先写""（分优点/问题/修改建议三条，问题必须具体到句子），
再写""（应用全部修改建议后的全文）。
{seed}
只输出 JSON。
```

### 模板 5 · 扩写 `kuoxie`（B 模式）

```
扩写。input 为下面的（原样使用）；
output 为扩写后的完整场景（300~600字）：加入环境细节、人物动作与对话、感官描写，有开头有收束，
避开平庸毛病（只概括不展开、人物脸谱化）。
{seed}
只输出 JSON。
```

### 模板 6 · 缩写 `suoxie`（A 模式）

```
缩写。input 为下面的（原样使用，一个字不改）；
output 为缩写版：压缩到原文三分之一左右，保留核心信息、关键情节与最有味道的意象，语言更凝练。
{seed}
只输出 JSON。
```

### 模板 7 · 提纲大纲 `dagang`（B 模式）

```
写故事大纲。input 为下面的（原样使用）；
output 为完整大纲：三幕结构（开端/对抗/结局）、主要人物一句话小传、至少5个关键情节点、结尾的情感落点。
{seed}
只输出 JSON。
```

### 模板 8 · 标题 `biaoti`（B 模式）

```
起标题。input 为下面的（原样使用）；
output 为：5个备选标题（风格各不相同：直白/悬念/意象/反差/金句），然后推荐1个并用一句话说明推荐理由。
{seed}
只输出 JSON。
```

## 3. 质量检查清单

脚本已自动处理标 ★ 的项，其余靠人工抽检。

1. ★ **格式校验**：JSON 可解析；`task/instruction/input/output/metadata` 四字段齐全；`task` 值在八类之内。
2. ★ **去重**：`input` 归一化（去空白）后取 sha256，全量去重；同一任务内 `output` 前 50 字重复的打印出来人工看。
3. ★ **长度过滤**：按下表过滤，不合格的丢弃并记日志。

| 任务 | input 长度 | output 长度 |
|---|---|---|
| xuxie 续写 | 10–300 字 | 80–1200 字 |
| gai_xie 改写润色 | 20–800 字 | 20–1000 字 |
| fengge 风格仿写 | 20–600 字 | 20–800 字 |
| piping 批评修改 | 20–800 字 | 100–2000 字 |
| kuoxie 扩写 | 10–200 字 | 150–1200 字 |
| suoxie 缩写 | 100–1500 字 | 30–600 字 |
| dagang 提纲大纲 | 10–300 字 | 150–2000 字 |
| biaoti 标题 | 20–600 字 | 30–600 字 |

4. ★ **内容禁区**：含"作为AI/语言模型/抱歉，我不能"等话术 → 丢弃；乱码或英文占比超 10% → 丢弃；`output` 与 `input` 完全相同 → 丢弃。
5. **人工抽检 ≥5%**：每类任务随机抽 5%，按"忠实度 / 文笔 / 多样性"三项 5 分制打分；任一项均分低于 3.5 分，该批次返工（换老师模型或调 temperature 重跑）。
6. **多样性记录**：题材标签（武侠/科幻/都市/历史/悬疑/儿童/情感/职场…）尽量覆盖，单一题材不超过 30%。

## 4. 运行方法（给张义的三步）

1. 台式机打开 **LM Studio**，加载老师模型（如 qwen3.8-27b），点 Start Server（地址 `http://localhost:1234`）。
2. 装依赖：`pip install requests`。
3. 运行：`python scripts/蒸馏数据批量生成.py` —— 输出在 `distill_output/` 目录，每类任务一个 `.jsonl` 文件；中途关掉重跑会自动续上，不会重复。

> 先用内置的少量种子小批量验证流程和质量，确认没问题后，把几千条种子写进 txt（格式：`task|种子文本`，一行一条），填到脚本顶部 `SEED_FILE` 再正式跑。
