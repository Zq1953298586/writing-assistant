# 微调效果评测方案（盲测）

> 目标：用 50 条写作 prompt，盲测对比「基座模型 vs 微调后的模型」，
> 回答一个问题：**这支笔是变利了，还是变钝了？**
> 评测人：张义自己 + 最好再拉一位朋友（自己评容易"越看越顺眼"，两个人更准）。

---

## 一、盲测集：50 条 prompt 怎么准备

**原则**：
1. 覆盖八类任务，数量按你平时用得多的来分配（建议分布如下）；
2. **不能从训练数据里抄**——抄了等于开卷考试，作弊；
3. 取材自你的真实写作场景（比如你正在写的 IP 剧本、小说段落），越真越准；
4. 每条 prompt 单独存一行，存成 `eval_prompts.jsonl`，格式：
   `{"task": "续写", "prompt": "……", "评分要点": "……（这条重点看什么，一句话）"}`。

**建议分布（共 50 条）**：

| 任务 | 条数 | 出题思路举例 |
|---|---|---|
| 续写 | 8 | 给一段你的小说/剧本开头，让它续 200 字 |
| 改写润色 | 8 | 找一段你觉得写得干巴的旧文，让它改生动 |
| 风格仿写 | 6 | 贴一段你喜欢的范文 + 你的草稿，让它按范文风格改 |
| 批评修改 | 6 | 贴一段有毛病的文字，让它批评并给建议 |
| 扩写 | 6 | 一句话梗概扩成一段 |
| 缩写 | 6 | 一段话缩成一句话 |
| 提纲 | 5 | 给主题列三幕式提纲 |
| 标题 | 5 | 给一句话起三个不同风格的标题 |

**先跑 5 条冒烟测试**：从上面挑 5 条最顺手的，流程走一遍，确认打分表好用，再跑剩下 45 条。

---

## 二、A/B 对比流程（关键：盲测）

1. **生成**：同一条 prompt，分别让基座模型和微调模型各写一次。
   - 参数固定：`temperature 0.7`，两边一样；
   - 写作类任务不要用 `temperature 0`（会写得干），也不要超过 1.0（会放飞）。
2. **编号**：把两份输出随机标成 A / B，**评测时不知道哪个是微调版**。
   - 最简单的办法：找朋友帮忙编号，或者自己用抛硬币决定后把对应关系写在纸上藏起来。
3. **打分**：按下面的打分表逐条打。
4. **揭晓**：50 条全打完再对答案，一条一条揭晓会污染后面的判断。

---

## 三、打分表（每条 prompt 一张）

| # | 维度 | 说明 | A 得分 | B 得分 |
|---|---|---|---|---|
| 1 | 文笔 | 用词准不准，有没有陈词滥调，读起来顺不顺 | /5 | /5 |
| 2 | 结构 | 段落起承转合、节奏，提纲/标题类看完整度 | /5 | /5 |
| 3 | 风格一致性 | 像不像"你"的笔，而不是通用 AI 腔 | /5 | /5 |
| 4 | 指令遵循 | 有没有按 prompt 的要求写（字数、风格、格式） | /5 | /5 |
| 5 | 综合 | 整体：这段文字你愿不愿意直接用 | /5 | /5 |
| 6 | 更好的是 | ☐ A  ☐ B  ☐ 差不多 | — | — |

打完 50 条，统计：
- **平均分**：微调版总平均 − 基座版总平均 = 提升值
- **胜率**：微调版"更好"（含"差不多"算平局）的条数占比
- **分维度看**：四个维度各自有没有退步

---

## 四、判定标准

### ✅ 训成了（可以投入使用）
同时满足：
- 微调版总平均分 **≥ 基座版 + 0.5 分**；
- 四个维度**没有一个**比基座版低超过 0.3 分（不能偏科）；
- "训歪信号"（见下）**零出现**；
- 风格一致性维度提升最明显（这是我们最想要的）。

### ⚠️ 可接受（能用，但值得再训一轮）
- 总平均分持平（±0.3 分内），但风格一致性有提升 → 说明方向对、火候不够；
- **对策**：数据加到 5000 条，或 `NUM_EPOCHS` 改成 3，再训一轮。

### ❌ 训歪了（回滚，不要用）
出现**任何一条**即判定训歪：
1. **复读/乱码**：同一句话反复出现，或冒出无意义字符；
2. **中英乱窜**：中文写作里夹带英文单词（专有名词除外）；
3. **拒绝写作**：对写作请求说"我做不到"，或答非所问讲大道理；
4. **风格塌成口水话**：比基座版更水、更 AI 腔（指令遵循维度掉 0.5 分以上常伴随这个）；
5. **指令遵循崩了**：让你续写 200 字，它写 2000 字；让起标题，它写正文。

**最常见的原因**：数据里混进了低质量样本，或某类任务数据太少（比如"批评修改"只有 50 条，模型就学歪了）。
**对策**：先回滚（见下），检查数据分布，补数据再训。

---

## 五、回滚操作（训歪了怎么办，2 分钟）

1. LM Studio / Ollama 里**切回原来的基座模型**（Qwen3-4B 官方版）继续用，写作助手 v1 网页版不受影响；
2. 训歪的 LoRA 权重**不要删**，留在 `output/` 里当反面教材；
3. 检查点在 `output/checkpoints/` 里，最近的 2 个还在——如果只是后半程训歪，可以从中间检查点恢复（喊我帮你看 loss 曲线定）；
4. 修数据 → 重训。**数据问题永远比参数问题更值得先查**。

---

## 六、多久评一次

- 每次训练完（4B 验证轮、8B 正式轮）各评一次；
- 以后加了增量蒸馏数据、重新训了，也评一次；
- 盲测集 50 条**固定不变**，这样不同轮次的分数可以直接比；
- 分数记下来，建个简单的对比表：

| 轮次 | 基座平均 | 微调平均 | 提升值 | 胜率 | 结论 |

| 8B 第一轮 |  |  |  |  |  |

笔是越磨越利，还是越磨越钝，这张表会诚实地告诉你。
